## R1 — malformed Bot API outcomes could erase recovery evidence

`Telegram::post` accepted a JSON object without checking that `ok` was a
boolean. `probe` could consequently treat a `STICKERSET_INVALID` description
with no valid outcome flag as proof that a set was missing. Provider recovery
could clear its durable intent and staged source using that unproved absence.
The mutation caller also treated such a reply as an explicit rejection without
consulting the available live-proof callback.

Reject missing, null, string, numeric, array and object `ok` values at the wire
admission boundary as `ApiError::Ambiguous`. Only an explicit boolean false plus
the missing-set error can establish `SetState::Missing`. An available mutation
proof callback must handle the uncertainty through the existing proof branch.
Without a callback, stop immediately: converting this new refusal into ordinary
`Transport` would introduce duplicate-prone retries for `sendMessage`. Preserve
the existing behavior for ordinary transport faults and explicit API outcomes.

The new cases in `supplemental_telegram_mutation_support/envelope.rs` use the
real HTTP parser and the existing owned numeric-loopback fixture. They assert
classification, request counts, waits, no unproved replay, and byte-for-byte
preservation of the durable state, mapping and staged image. Existing applied,
not-applied and unknown proof cases remain in the same target.

## R2 — a blank optional note prevented valid pack publication

A 4096-space note, or a similarly long tab/newline note, passed validation and
was truthy. `renderAnnouncement` made it a standalone first message when the
following pack did not fit the same chunk. Telegram rejects empty text, so the
send failed before the valid pack link and `/publish` returned 502.

Apply the existing length cap first, then include the note only when
`note.trim()` is nonempty. Send the original capped text when it contains real
content, preserving its intentional leading and trailing whitespace. No API,
authentication, chunk-size or successful-send acknowledgment contract changes.

The route-level regressions reject blank outgoing text at the transport boundary
and require HTTP 200, exactly one send and the expected pack link. A separate
positive control preserves meaningful whitespace. All original Worker tests
remain in the complete suite.

## R3 — gallery callbacks restarted media during a freeze

The gallery paused media when the document became hidden or scrolling started,
but an already queued IntersectionObserver delivery checked only the master
switch and the initial reduced-motion setting. It could restart animated images
and video while hidden or scrolling. Switching animation on, returning to the
page during scrolling, and the scroll thaw timer had the same missing gate.

Use one `mayAnimate()` predicate for the master switch, reduced motion,
`document.hidden` and the active scroll thaw timer. Enforce it at `setLive`,
where every media-start path converges, and in `applyAnim`. Preserve normal
visible playback, master Off, reduced-motion behavior and the existing thaw
interval.

The scroll debounce must track every non-reduced-motion scroll even while the
master switch is Off. Otherwise Off -> scroll -> On at 1 ms starts media before
the documented 180 ms quiet interval. A later scroll while temporarily Off also
fails to reset the old deadline: enabling at 101 ms after scrolls at 0 and 100 ms
must remain frozen through 279 ms and resume at 280 ms. Both counterexamples
failed against `ee6d88ae`; two settled/active-scroll controls passed. Remove only
the animation-switch part of the scroll handler's early return; keep the
reduced-motion refusal and the common admission predicate. All original eight
actual-script VM cases and all four new boundary/control cases then pass.

The browser helper `assets/tests/fixtures/gallery-motion.js` executes the real
gallery script and CSS with real WebP/WebM media and native observers. An
independent observer delivery barrier prevents assertions from passing before
the race occurs. Hidden, scrolling, toggle, visibility re-entry and thaw cases
are exercised with positive playback controls. All original F05 assertions and
all 156 panel-suite identities remain present: 97 browser/performance cases plus
59 served-source contracts.

Three additional browser substeps cover initially-Off scrolling, the latest
scroll during an Off interval, and remaining Off through expiry before enabling.
Only their 180 ms debounce timer is controlled; native observers, animation
frames, real scroll events and media remain real. The original real-time cases
remain unchanged. Check normal playback before installing the narrow timer
controller, and use native observer/scroll barriers before asserting states.

The historical `tests/fixtures/backend/gallery.json` stays immutable. Both
`original_main_rust_gallery_parity` and the independent `baseline_cli_status`
whole-roster/gallery oracle use `runtime/tests/support/gallery_oracle.rs`. The
shared helper admits only the three literal, reviewed script changes, asserting
that each old fragment occurs exactly once before complete document equality.
The full-suite run exposed the second consumer; the consumer inventory covers
all frozen-corpus and renderer references. Only that mapped test's mutable target
body receipt in `tests/fixtures/migration/reference-cases.json` is refreshed;
original identities, historical hashes and golden HTML are unchanged. Do not
strip the script or derive the expected result from the current source.
The final scroll-guard delta changes only that strict helper: both mapped caller
bodies and the existing mutable mapping receipt remain unchanged.

## R4 — terminal relaunch changed the selected pack numbers

`run-panel.ps1` joined an integer array with commas and passed it to a new
`pwsh -File` process. That process receives strings, not the original typed
array. A supplied `6,7` became one value, `67`; `1,2` became `12` and `6,7,8`
became `678`. Joining arguments also risks losing exact user input at a second
command-line boundary.

Use a data-only relaunch payload containing the script path and typed bound
parameters. A fixed encoded PowerShell command decodes the payload and splats
the reconstructed hashtable into the script. Preserve integer arrays, switches,
empty strings, Unicode, spaces, quotes and semicolons as data. Do not build code
from raw command arguments. Keep the `NoRelaunch` guard and error-pause behavior.

Plain JSON decoding also coerces timestamp-shaped argument strings to DateTime.
Both actual-child regressions reproduced this after the first transport repair.
Encode every string leaf before JSON and decode it recursively after parsing;
preserve nested argument arrays, booleans and integers. This closes the UTC,
offset, fractional and timezone-free timestamp cases without depending on the
PowerShell 7.5-only `DateKind` option; the launchers still support PowerShell 7.3.

## R5 — a failed log sink prevented the application from starting

Creating or finding the `logs` directory did not prove that `Add-Content` could
write the log. The first write could throw before native execution, and the
error handler called the same failing logger again. This turned an optional
diagnostic failure into a launcher failure and could hide the original result.

Catch sink failures inside the logger, disable that sink for the remainder of
the invocation, emit one timestamped WARNING and continue native execution.
Preserve INFO, WARNING, ERROR and DEBUG categories; never log command arguments,
encoded payloads, tokens or credentials. A logging failure must not change the
native exit code or recurse through the same failed sink.

## R6 — inherited PowerShell preferences changed native exit codes

With `$PSNativeCommandUseErrorActionPreference = $true`, the launchers'
`$ErrorActionPreference = 'Stop'` converts a nonzero native exit into a terminating
PowerShell error. The catch block then returns 1 instead of the application's
actual result, such as 3 or 7.

Keep direct PowerShell native invocation, set Standard argument passing and
disable native-error preference in the script scope, then capture `$LASTEXITCODE`.
Declare PowerShell 7.3 as the minimum that supports the required argument
semantics. Preserve caller preferences, pipeline capture, console/process
ownership and genuine validation/missing-executable failures. A direct
ProcessStartInfo replacement was rejected during review because it bypassed
the caller's PowerShell stdout pipeline; both launchers retain a regression
for this observed candidate defect.
