# Native test migration evidence

The expanded first-party migration is in progress. Authored Rust tests and source
case mappings are not passing tests, source-retirement permission or acceptance
of an installed package. Retained original sources and independent fixtures remain
necessary until the full migration gates pass.

## Similarity boundaries

Three observations answer different questions:

- The pure Rust similarity suite compares the independent greedy and near-hash
  fixture results. A separate historical worker regenerates the entire original
  fixture document from pinned Git source and rejects coordinated fixture drift.
- The registered PyO3 binding suite calls the actual exported functions, including
  unsigned-integer extraction, exact Python exception classes and two concurrent
  callers. The outer Python attachment is released before joining those callers.
- The historical catalog cohort preserves the two unchanged missing-module
  assertions with the original similarity functions and Catalog. Private imports
  prevent application-module execution; the original patch must be restored,
  failed prerequisite admission must create no database and the acknowledged
  temporary directory must remain empty before cleanup.

A compiled Rust executable cannot lose its linked similarity implementation in
exactly the same way that a Python import fails. Historical import-failure
assertions therefore remain distinct from native installation verification. The
existing contributor-builder command test separately checks missing Cargo:
exit 2, a useful Rust prerequisite diagnostic, an ERROR file-log entry and no
created environment, runtime or build output. Signing admission is a later gate,
not an alternative successful installation.

These binding, catalog and builder additions are authored, uncompiled and unrun.
Actual ABI, error, concurrency, timing, cleanup and platform acceptance is pending.
